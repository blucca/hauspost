# Recorded demonstration

[Watch the 104-second film](https://blucca.github.io/hauspost/demo/).

The first model request is an actual Apertus 1.5 8B Q4_K_M CPU request inside the on-prem Docker stack, run 38328626014, taking 87.917 seconds. The waiting interval is shortened in the film. The model returned an intercom description for the synthetic apartment-doorbell complaint.

The source-review and handoff segments replay that exact response in the live browser application, labelled Recorded Apertus 8B result. Scripted coordinator actions refine the fault description to the apartment doorbell, review the repaired tap and changed visits, draft a German missing-unit question, add unit 3B as Coordinator entry and create the handoff.

The difficult-case segment loads the original English footer result from the same CI batch. Its 99Z value cites Apartment 4B. The post-run copied-value check blocks confirmation; visible coordinator edits correct the unit, active fault and resolved-issue source. The model's original failures remain public in the evaluation data.

Synthetic correspondence, scripted review decisions and synthesized English narration are used throughout. The film has H.264/AAC tracks, burned-in subtitles, a separate 18-cue English VTT and a full transcript. Source/UI recording precedes editing; reading pauses and CPU wait compression follow the actual action order.
